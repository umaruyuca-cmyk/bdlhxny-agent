三种架构对照

同一题库、同一 LLM、同一份数据，唯一变量是编排形态。本页逐一给出三种形态的完整调用链路与工具选择机制；对照回答一个问题：Agent 工程模式的价值，相对「大家都会写的第一版」和「框架默认形态」到底有多大、来自哪里。

基线

裸 tool calling

LLM 原生 tool calling：全量工具塞入上下文，无治理、无装载策略、无快路径、无输出护栏。多数人跟着教程写出来的第一版。

对照组

LangGraph 官方 ReAct

create_react_agent 框架默认编排：ToolNode 统一执行（非法工具名回错误观察），recursion_limit 控步数。回答「框架默认够不够」。

本系统

完整工程模式

scoped 场景装载 + G1–G7 治理中间件 + 语义快路径 + Output Guardrail。模型提议，代码裁决。

调用链路

① 裸 tool calling：全量装载 + 无门禁直执行

系统提示 + 用户消息 → llm.bind_tools(全量工具 spec) ← 目录里所有工具一次性进入模型上下文 → LLM 生成 ├─ 无 tool_calls → 文本即答案，结束 └─ 有 tool_calls → executor(name, args) 直接执行 ← 无任何校验层 → 结果 JSON 回填 ToolMessage → 重新调用 LLM → 循环上限 10 轮，耗尽即止
环节行为
工具选择模型在全量目录里自由挑选，没有任何缩小选择面的机制
执行口executor 本身：幻觉工具名、越权调用、参数错误全部直达执行面
终止条件模型不再发起调用，或轮次耗尽
输出防护无：模型答案原样返回

② LangGraph 官方 ReAct：框架状态图 + ToolNode 统一执行

系统提示 + 用户消息 → create_react_agent(model, tools, prompt) 内部为一张状态图：agent 节点 ⇄ tools 节点，条件边判断是否继续 → agent 节点（LLM + bind_tools 全量工具） ├─ 无 tool_calls → 条件边 → END，输出答案 └─ 有 tool_calls → tools 节点（ToolNode 统一执行口） ├─ 合法工具名 → args_schema 校验 → 执行 → ToolMessage └─ 非法工具名 → 不执行，错误观察回填给模型 → 条件边 → 回 agent 节点 → recursion_limit 控制总步数（模型步与工具步各计一步；耗尽以固定消息收尾）
环节行为
工具选择仍是模型在全量目录里挑——选择面与基线相同，框架不裁剪
执行口ToolNode：第一个「执行口收拢」，非法工具名在此拦截（回错误观察，而非到达执行面）
框架提供状态图编排、条件边、步数上限、参数 schema 校验
依然没有权限、预算、只读红线、审计、装载策略、输出侧数字接地

③ 完整工程模式（本系统）：三层闸门 + 唯一执行咽喉

输入（固定用例和版本化上下文） → G-α 语义快路径（embedding 相似度分流） ├─ 闲聊 → 罐头应答（零 LLM、零工具） ├─ 知识 → 单次 LLM 直答（零工具装载） └─ 禁止语义 → 结构化拒绝 + 审计码（零执行） → 未命中 → AgentLoop 进入循环 → 工具装载（代码决策，未装载的工具对模型不可见） ├─ scoped（默认）：场景标签 → 工具包映射表 → 固定子集 └─ search：仅装载 search_tools 元工具 → 模型发起检索 → 权限过滤先于检索 → embedding top-k 召回 → 命中动态装载 → 连续 2 次未命中 → 回退 scoped 宽包 → 每轮循环： LLM bind_tools(当轮装载集) ├─ 无 tool_calls（G-β 直答）→ 文本答案，零工具调用 └─ 有 tool_calls → 治理中间件（唯一执行咽喉，逐层裁决） G1 可见性：工具名 ∈ 当次装载集？ ← 幻觉工具在此拦截 G2 只读：read_only 红线 G3 权限：游客 / 机主 + required_scope ← 越权调用在此拦截 G4 预算：调用上限 + cost_hint 加权（premium ×3） G5 参数：pydantic schema 校验 → 执行（固定数据适配器或确定性本地计算） G6 Observation 包装：来源 / 数据时间 / 质量标记 G7 审计：调用者 / 工具 / 参数摘要 / 耗时 / 状态 / 审计码 → Observation 回填 → 下一轮 → Output Guardrail（输出侧最后一道） 数字接地：答案中非平凡数字必须来自某条 Observation C-1 / C-2 合规复核 → 违规处修正后输出 → 结果块（blocks）由 Observation 直接投影，不经 LLM 转述
环节行为
入口G-α 快路径：闲聊 / 知识 / 禁止三类不进循环、不装载工具，成本与延迟直接归零
工具选择两段式：代码先裁「可见集」（scoped 映射或 search 检索），模型只在可见集内选择
执行口治理中间件是唯一执行入口，所有固定数据工具走同一拦截链
终止条件模型直答（G-β）或预算耗尽（G-γ）；每次调用都有审计码
输出防护数字接地 + 合规复核；事实性数字由工具输出投影，模型只产出解读文本

实验设置

控制项做法
题库18 道固定题：闲聊 / 知识 / 注入防御 / 越权 / 多轮指代 / 金融研究 / 组合 / 适合度 / 记忆 / 估值链
模型三组使用同一 LLM 与温度，排除模型差异
工具执行只使用版本固定的工具数据；三组共享同一份输入和返回，隔离外部服务波动
路由金标快路径（GoldRouter），隔离路由误差
判官全部机械断言（集合相等 / 数字接地 / 审计码），无 LLM 判官
