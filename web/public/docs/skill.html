工具目录与治理

统一 ToolCard 目录描述固定数据工具和本地确定性计算；治理中间件对所有工具使用同一拦截链。本系统比较 Agent 实现方式，不把工具集合包装成业务 Skill。

ToolCard

七字段契约：

字段说明
name工具唯一名
description双目的描述（模型选型 + 人读）
parameters参数 schema（pydantic 投影）
origin冻结数据 / 本地计算
read_only是否只读
required_scope权限范围
cost_hint预算 / 成本提示
C-1：交易语义工具在目录中物理不存在，而非运行时「隐藏」。

治理中间件 G1–G7

编号职责
G1可见性：未装载工具不可调用
G2只读：写操作受 read_only 约束
G3权限：required_scope 校验
G4预算：轮次 / token / 工具次数
G5参数：schema 校验
G6Observation 标准化
G7审计码落证据链

被拒工具在 tool.step 上呈现失败态与审计码；终帧 response.final 汇总 disclosures / audit_codes。

红线 C-1 / C-2

  • C-1：不具备任何交易执行能力；「帮我买入」类请求被拦截并返回审计说明。
  • C-2：适合度输出仅为风险匹配筛查草稿（SuitabilityDraft）。固定披露：本结果仅为风险匹配筛查草稿，不构成投资建议。禁止「适合 / 推荐买入」话术。
  • C-4：演示注入 source=demo_inject 须在负载、通知、证据链、UI 四处可辨识。

固定数据工具

正式对照不访问实时外部服务。行情、资讯、搜索和用户数据都冻结成有版本的工具返回；本地确定性计算仍以 ToolCard 登记。

接入清单（摘要）

  1. 用 ToolCard 七字段登记；交易类工具不得入库。
  2. 冻结数据工具与本地计算共用 G1–G7 拦截链。
  3. Observation 带 result_type，供前端 Block 直接投影。
  4. 失败可重试的外部调用需可观测（审计码 + degraded），不得静默吞错。

对接细节见仓库内 CHAT_INTEGRATION.md / API_INTEGRATION.md。
