核心主张：模型提议，代码裁决

模型负责（提议）

语义判断

场景与意图分流（embedding 快路径）；在装载集内选择工具与参数；解读与表达。

代码强制（裁决）

确定性边界

裁剪模型可见的工具集（scoped | search）；G1–G7 治理中间件是唯一执行咽喉；预算与只读红线；输出数字接地与结果块投影。

不接受概率裁决：权限、预算、红线这类不可挽回的决策全部由查表和中间件确定执行，不交给模型判断；交易类工具物理上不在工具目录中（红线物理化）。

产品载体：Agent 对照实验

项目所有者登录后选择固定题号，系统用同一模型、上下文和冻结工具数据运行三种 Agent 实现。公开访问者只能查看经过发布检查的结果，不能输入问题或触发运行。

固定用例 + 固定上下文 + 冻结工具数据 → baseline tool calling / LangGraph ReAct / full-system → 记录上下文、工具、耗时、token 和判断结果 → 发布静态结果

业务模块

EVAL

tests/eval

对照 runner：18 题固定题库 × 三组编排 × 可复判官；报告落 report.json 供本站渲染。

ENGINE

engine + guardrails

Agent 循环、语义快路径、scoped | search 工具装载、G1–G7 治理中间件、输出护栏——被测 treatment 系统。

TOOLS

tools + registry

ToolCard 统一目录（重名 / 交易语义 / 只读三关）与资格真源；对引擎与基线同等暴露。

CONSOLE

web

本展示站：纯静态、零后端依赖，证据页面消费真实运行产物。

对照实验的可信度约定

约定说明
同一题库18 题固定题库，覆盖闲聊 / 知识 / 拦截 / 金融研究 / 组合 / 适合度 / 多轮指代
同一数据canned 工具观察，三组共用，隔离执行质量差异
代码判官全部指标由确定性断言产生（成功执行集相等 / 数字接地 / 违规语义扫描）
失败样本保留失败工件原样归档，不挑选、不删改

整体架构

数据服务保存固定条件，运行引擎执行对照，公开站只展示已经发布的静态结果。

项目所有者 → 私有运行 API（只接受 case_id） → data（固定题库 / 版本 / 运行记录） → Python Engine（baseline | react | full-system） → 冻结工具数据 + 上下文构建 → 评测结果 → 静态公开数据 → Console
边界：展示站无后端依赖、无交互输入；评测与引擎在本仓库 engine/ 内闭环复现。

固定批次链路

项目所有者发起

选择固定题号与实验配置 → 语义快路径或 Agent 循环 → bind_tools + 治理中间件 → token / tool.step / response.final → ResultBlock + 证据链上屏
无对话入口：不提供自由对话页面；评测输入即固定题库，输出即证据工件。
