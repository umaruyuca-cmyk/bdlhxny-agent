# 站点信息架构与模块内容

依据 2026-08-21 所有者反馈重构(两轮):现有站点"实证层 /showcase + 讲解层 /docs"
两层混排不清。目标结构:**顶栏 = 模块,点击模块后侧边栏展开该模块的细则页面**;
首页集中展示项目总结、整体架构与 GitHub;**上下文压缩单独立模块**(展示计算逻辑
与长→短对照实验);**评判标准单独立顶栏**(编排对照与上下文对照复用同一套)。

## 1. 导航模式

```text
顶栏(模块级,7 项 + 外链)
  首页 | 实证展示 | 对照实验 | 上下文压缩 | 评判标准 | 引擎与治理 | 数据与运行 | GitHub(外链)
        └─ 点击模块 → 模块首页,左侧边栏展开该模块的全部细则页
侧边栏(模块内页面级)
  上半:模块页面清单(当前页高亮)
  下半:当前页的本页目录(锚点,沿用现有 scroll-spy)
```

- 每个模块一个 URL 前缀与一个模块首页;
- 公开页铁律不变:纯静态、零后端调用、无输入控件(唯一例外 /lab);
- 旧 `/docs/*`、`/showcase/context` 路径 301 到新位置;`/showcase-data/` 数据管线不变。

## 3. 模块一:首页 `/`

单页五节,回答"这是什么项目、它做哪两类实验"。

### 3.1 项目定位与总结

- **是什么**:Agent 编排模式对照实证平台(Touchstone),不是公开聊天产品;
- **核心主张**:"模型提议,代码裁决"——语义判断归模型,权限/预算/红线由代码确定执行;
- **两大实验轨道**:
  1. **编排对照**:同一 18 题题库、同一 LLM、同一份冻结工具数据,对照裸 tool calling /
     LangGraph 官方 ReAct / 完整工程模式,量化工具选择、幻觉抑制、权限拦截;
  2. **上下文压缩对照**:同一长上下文用例,全量透传(full)与按预算压缩(budgeted)
     两种处理分别跑同一 Agent 逻辑、用同一套评判标准,量化关键事实保留、token 净节省;
- **证据方式**:全部指标由代码断言产生,无 LLM 判官;未运行显示"未运行"。

### 3.2 整体架构

- **服务拓扑图**:web(纯静态)/ engine(私有运行 API + 执行)/ data(题库与记录)/
  PostgreSQL(唯一真源);公私边界:公开部署只含静态站;
- **一次运行的流程图**(编排轨道):登录 → 按题号发起 → 冻结数据 → 三组执行 →
  工件 → 发布校验 → 静态展示;
- **上下文压缩链路图**(压缩轨道):长上下文条目 → 分类 → 预算选择 → 压缩 →
  工作上下文 → 同一 Agent 循环 → 同一判官;
- **变量隔离**:编排对照用冻结数据隔离执行质量、金标路由隔离路由误差;
  压缩对照只变上下文处理策略,其余全部固定。

### 3.3 两套题库

- 编排对照 18 题(闲聊/知识/拦截/研究/组合/适合度/多步);
- 上下文压缩 6 套长上下文用例(金融 3 / 其他 2 / 闲聊 1),每套两条变体
  (full-raw 全量 / budgeted-comp 压缩),均入库为唯一真源。

### 3.4 当前进展与关键数字

- 已落地清单 + 路线图一行(P3-1 工件与有效性 → P3-5 发布全量校验 → P3-2 压缩接入);
- 关键数字卡:最新批次三能力指标(数据驱动,未达门槛诚实提示)。

### 3.5 仓库与复现

GitHub 地址(顶栏常驻外链)、目录一览、复现三步、工程门禁命令。

## 6. 模块四:上下文压缩 `/context/`(第二实验轨道)

侧边栏:压缩算法 / 长短对照设计 / 用例结果。

### 6.1 压缩算法(计算逻辑)

展示 `engine/src/bdlh_runtime/context/` 的完整计算逻辑,配流程图与一个具体条目
在每一步的去向示例:

1. **条目分类**(进入候选前必归一类):
   - 强制保留:安全规则、当前目标、关键数值、权限、数据时间——原文/无损保留;
   - 可压缩:历史交易、长序列、新闻集合、财报章节——按字段或主题汇总,保留来源引用;
   - 仅引用:当前不必全文的长文档——工作上下文存摘要+引用;
   - 干扰信息:过期、重复、无关、跨用户、外部指令——降权/隔离/拒绝;
2. **token 估算**:CJK 每字 1、latin 除以 4(ConservativeTokenCounter,接入真实
   tokenizer 后替换并标注版本);
3. **预算选择**:按 priority + 预算贪心选择;**required 条目永不淘汰**;
   强制项自身超预算 → 明确失败(required_overflow),不静默删规则;
4. **结构化压缩**:分组汇总(如 500 条交易按标的/月份聚合),压缩后保留引用链;
5. **校验**:强制项保留率必须 100%;引用完整;跨用户内容进隔离区;
   注入文本包 `<untrusted-data>` 标签,不进指令区;
6. **可解释输出**:每个保留/压缩/引用/省略决定带原因,进上下文处理报告。

### 6.2 长短对照设计

- **实验单元**:同一用例 × 两条变体——`full-raw`(全量透传,大预算)与
  `budgeted-comp`(按预算压缩,小预算);**同一 Agent 逻辑、同一冻结工具数据、
  同一套评判标准**(→ 评判标准模块),唯一变量是上下文处理;
- **用例矩阵**(6 套,已入库):

| 用例 | 方向 | 问题要点 | 压缩考察点 |
|---|---|---|---|
| ctx-port-01 | 金融·组合 | 持仓总值/风险/换房目标 | 冲突值(旧目标/旧画像)、30 持仓+500 交易汇总 |
| ctx-val-01 | 金融·估值 | 估值区间+三个关键假设 | 多期财务口径、同行比较、过期报告 |
| ctx-news-01 | 金融·新闻 | 去重后按重要性列消息 | 50 条去重、官方优先、注入文本隔离 |
| ctx-weather-01 | 其他·出行 | 带伞/温差 | 30 天×3 城市序列汇总、旧预报冲突 |
| ctx-manual-01 | 其他·长文档 | 指示灯含义与恢复 | 关键事实埋中部、旧版本章节冲突 |
| ctx-chat-01 | 闲聊 | 闲聊快路径 | 长历史下规则保留、快路径零工具 |

- **胜负判据**:任务成功 + 关键事实召回(required_facts/forbidden_facts)+
  强制项保留率 + token 净节省(压缩有额外成本时要算净额);
- **现状**:变体与数据已入库;执行接线依赖 P3-2(上下文构建器接入三种运行),
  接线前本页展示设计,用例结果显示"未运行"。

### 6.3 用例结果(数据驱动)

- 6 用例 × 2 变体结果表:原始 token / 工作 token / 压缩比例 / 强制项保留率 /
  关键事实正确 / 引用完整 / p50·p95 时长 / 状态;
- 正反例成对展示(同用例成功 vs 失败运行,标注唯一变量与失败原因);
- 数据源:`showcase-data`(上下文批次发布产物);原 `/showcase/context` 页迁入。

## 7. 模块五:评判标准 `/judging/`(全部实验共用)

侧边栏:指标定义 / 判官说明 / 无效运行与口径。

### 7.1 指标定义

- **能力指标 6 项**(编排与压缩对照通用):工具选择准确率、幻觉工具率、越权泄漏率、
  数字幻觉率、C-1 违规率、C-2 违规率——每项定义原文、计算口径、方向;
- **效率指标 4 项**:平均轮次、平均 token、p50/p95 时长;token 估算口径标注;
- **上下文专项**(仅压缩对照):强制项保留率、关键事实召回率、引用完整率、
  token 净节省 = (未压缩成本 − 压缩后总成本),压缩额外消耗计入。

### 7.2 判官说明

- 全部代码断言:成功执行集==期望集 / 目录外工具名扫描 / absent_tools 越权交集 /
  数字接地(非平凡数字必须落在某条 Observation)/ C-1·C-2 语义扫描;无 LLM 判官;
- **上下文对照复用同一套**:工具/数字/合规断言原样适用,新增上下文断言
  (required_facts 出现、forbidden_facts 未当当前事实、required_items 保留);
- GoldRouter 金标路由与冻结执行器:两轨道共用的误差隔离手段。

### 7.3 无效运行与口径

- INVALID 定义(429/余额不足/服务不可用/工件不完整)不进能力指标分母;
- 每组有效样本门槛;0%→0% 不描述为改善;报告数字可回算到工件。
