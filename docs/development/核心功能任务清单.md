## 任务一:统一运行工件与运行事件落库

**现状**(2026-08-21 审计):执行期纯内存——批次完成只写聚合级记录
(run/evaluation/complete_run);`validRun` 硬编码 `true`,429 类无效运行分不出;
`snapshotId`/`variantId` 是拼接字符串,不关联真实 `data_snapshots`/`case_variants`;
工件为裸 JSON 无 hash 无 schema;库里的明细表全部空置。

**改动步骤**:

1. **事件定义与埋点**(架构文档 §4.3 九类):`run.started`、`context.completed`、
   `model.completed`、`tool.requested`、`tool.completed`、`guardrail.completed`、
   `output.completed`、`judgment.completed`、`run.completed`。内存事件总线即可
   (不引消息队列);三组执行器(裸调用/ReAct/完整模式)同口径埋点。
2. **逐步落库**:事件与明细写入既有表——`run_events`(事件流)、`model_calls` +
   `model_call_messages`(每轮模型输入输出)、`tool_calls`(每次工具执行)、
   `guardrail_checks`(拦截明细)、`run_measurements`(分阶段耗时)。经 data 服务
   新增 internal 接口写入,engine 不直连库(与现有边界一致)。
3. **统一运行工件**:按评测文档 §9 schema(artifact_version/status/validity/
   case/experiment/provenance/context/steps/result/judgment/timing/tokens/
   artifact_hash)落 `run_artifacts` 表 + ARTIFACTS_DIR 文件双写;hash 可复算。
   provenance 记录 git_commit、tool_catalog_hash、**真实** snapshot_id 与 variant_id
   (从 case_variants/data_snapshots 取,消灭拼接字符串)。
4. **有效性分类**:429/余额不足/模型服务不可用/工件写失败 → `INVALID`;
   运行状态机按架构文档 §7.1 六态;`validRun` 不再硬编码。
5. **指标改口径**:`_summarize`/报告只用 VALID 运行;无效运行单列(数量+原因分组);
   单次运行可从汇总下钻(依赖 run_id 贯穿)。

**验收**:每运行有 run_id、用例版本、快照 hash、git commit、模型配置;429 注入
用例标 INVALID 且不进成功率;`run_events`/`tool_calls`/`guardrail_checks` 有真实
数据;工件 hash 复算测试通过;批次完成后 /lab 对应批次在库内可查逐步明细。

**回归**:engine pytest 全绿 + 新增工件/事件契约测试;data mvn test(新接口)。

## 任务二:上下文构建器接入与长上下文对照执行

**现状**:`context/` 包已实现四策略(FULL/RECENT_N/SINGLE_SUMMARY/BUDGETED)、
required 保留、跨用户隔离、`<untrusted-data>` 包裹,但 AgentLoop 仍用
`_assemble_messages` 直接拼消息(loop.py:144,218),全仓库仅测试引用;token 为
字符估算;ctx 用例 12 条变体在库中但执行链路不读变体。

**改动步骤**:

1. **接入循环**:AgentLoop 消息拼装改经 `ContextBuilder.build()`;第一版 FULL
   策略完整透传(行为与现有一致)+ 产出上下文处理报告;所有模型输入必须过构建器。
2. **变体感知执行**:eval runner 接受 (case, variant) 二元组;从库里读变体
   context_items(优先 `fixture_context_items` 正规表,兼容 `data_fixture` JSONB)
   与 `context_strategy`;运行记录关联真实 variant_id。
3. **压缩对照 runner**:六套 ctx 用例 × (full-raw / budgeted-comp) 两变体,
   同一 Agent、同一冻结工具数据、同一判官(工具/数字/合规断言复用);新增上下文
   断言:required_items 保留率 100%、required_facts 出现、forbidden_facts 未当
   当前事实、注入条目未进指令区。
4. **处理报告进工件**(依赖任务一):原始/工作 token、保留/压缩/引用/隔离/省略
   计数与逐条原因、构建耗时;强制项超预算 → `required_overflow` 失败,不静默降级。
5. **tokenizer**:接入 GLM tokenizer 或保持 ConservativeTokenCounter,但版本号
   写入工件与处理报告(`tokenizer_version`),口径可辨。

**验收**:所有模型输入经构建器(架构测试守卫);六套用例两变体各跑通一轮真实
批次;强制项保留率 100% 断言通过;关键事实位于开头/中间/末尾的单元测试通过
(ctx-manual-01 已覆盖中部);`context_decisions`/`context_messages` 表有真实数据。

**回归**:engine pytest(新增 context 对照测试);冒烟批次后 `run_events` 中
`context.completed` 事件存在。

## 任务三:评测有效样本门槛与交错运行

**现状**:`runs_per_case` 默认 5 只是重复次数;题序固定、三组相邻串行;错误运行
计入指标分母(`error_count` 仅单列);无"每组有效样本达标"判定。

**改动步骤**:

1. **交错运行**:同一题的 N 次重复之间打乱三组顺序(题序可轮转),避免先跑组
   总遇到更好服务状态;
2. **有效样本门槛**:批次级判定——每组 VALID 运行数 ≥ 5(可配置)才满足门槛;
   门槛状态写入批次记录与工件;
3. **报告修正**:总运行/有效/无效三分;无效按原因分组;0%→0% 不再渲染为
   "改善/回归";每个汇总数字可回溯到 run_id(任务一地基);
4. **批次语义**:未达门槛批次可运行、可查看,但不可认定正式(供任务五消费)。

**验收**:交错用确定性种子(可复现);构造 3 有效+2 无效(429 注入)的批次被
判未达门槛;渲染测试断言无 0%→0% 改善文案。

## 任务四:批次取消、token 上限与运行详情页

**现状**:无取消端点;无批次级 token 预算(`runs le=5` 只是次数);/lab 只显示
完成/失败两态;无单次运行详情视图。

**改动步骤**:

1. **取消**:`POST /api/v1/jobs/{id}/cancel`——置协作取消标志,运行循环在轮次/
   工具调用间隙检查;已起模型调用等待完成,不硬杀;运行状态落 `CANCELLED`,
   已完成部分照常落工件(部分完成语义);
2. **批次 token 上限**:`EvalBatchRequest` 增加 `max_total_tokens`(可选,默认取
   环境变量);runner 累计消耗,超限停止发起新运行并标记原因(区别于 INVALID);
3. **/lab 运行详情**:批次 → 运行列表 → 单次运行逐步视图(读任务一的事件/工件
   接口),含每轮模型决策、工具调用、guardrail 判定、耗时 token;取消按钮。

**验收**:取消后作业进 CANCELLED 且工件完整;token 上限注入用例停止后续运行;
/lab 能下钻到单步;幂等重复取消无副作用。

## 任务五:发布校验全量版与正式批次认定

**现状**:发布脚本 v1 只做白名单投影,validity 全标 `UNCLASSIFIED`、
`is_formal` 恒 false(P3 诚实占位);无敏感扫描、无 hash 链校验、无门槛判定;
`runs/{id}.json` 未发布(单次运行页显示"未发布")。

**改动步骤**:

1. **输入升级**:发布输入改为任务一的运行工件目录(逐 run 工件),不再是
   latest.json 聚合;
2. **全量校验**(评测文档 §12):最小有效样本门槛(消费任务三判定);敏感信息
   扫描(密钥/系统提示/内部地址/未脱敏用户数据,零容忍);公开引用全部可解析;
   每个公开工件 hash 与索引一致;无效运行不冒充失败样本;
3. **产物升级**:`runs/{id}.json` 九段工件发布(run.schema 已就绪);批次报告
   validity 换真实值;`index.formal_batches` 填入满足门槛批次;
4. **正式批次认定**:`is_formal=true` 仅当门槛满足且校验全过;`UNCLASSIFIED`
   退役;公开 publications/publication_runs 表登记发布记录;
5. **发布页提示**:发布失败给出具体原因清单,不部分发布。

**验收**:跑一轮满足门槛的真实批次(18 题×5 次)→ 发布 → 首页显示"最新正式
批次";敏感字段注入用例发布失败且报出字段名;runs 页有真实单次数据;hash 复算
通过;未达门槛批次发布被拒并说明。
