# 用户登录功能设计任务书（Prompt）

## 背景
Touchstone 是固定用例 Agent 对照评测系统。系统只有两类使用者：**项目所有者**（登录后运行固定用例）和**公开访问者**（只读静态站，不登录）。当前 `engine/src/bdlh_runtime/run_api.py` 用静态令牌 `_require_token`（环境变量 `RUN_API_TOKEN`）做单一后端保护，需升级为账号密码登录 + 会话校验。

## 目标
实现项目所有者的登录/登出/会话校验，替换静态 `RUN_API_TOKEN`，全程可审计，仓库与数据库不落明文凭证。

## 架构约束（必须遵守）
1. **登录逻辑在 Python（FastAPI）**：用户入口是 `engine` 的 `run_api.py`（`/api/v1/*`）。
2. **账号/会话数据原语在 data 服务（Spring）**：engine 不直接连 PostgreSQL，通过 `DataClient` 调用 data 的 `/internal/v1/auth/*`。
3. **服务间认证**：engine → data 继续用 `X-Internal-Token`（`InternalTokenInterceptor` 已有）。
4. 公开静态站（`web`）不涉及任何登录。

## 数据模型（已建表，直接使用，勿改）
`db/postgresql/setup/06-create-accounts-tables.sql` 已定义：
- `accounts`：`id`(UUID)、`username`(唯一)、`display_name`、`password_hash`、`status`(ACTIVE/LOCKED/DISABLED)、`failed_attempts`、`locked_until`、`last_login_at`。
- `auth_sessions`：`id`、`account_id`、`token_hash`(唯一)、`expires_at`、`last_seen_at`、`revoked_at`、`ip_address`、`user_agent`。
- `audit_log`：`id`、`account_id`、`action`、`succeeded`、`detail`、`ip_address`。

## 安全要求（硬性）
1. 密码只存 bcrypt 加盐 hash（`gen_salt('bf', 12)`），校验用常量时间比较。
2. 会话令牌为高熵随机值（如 `secrets.token_urlsafe(32)`），数据库只存 `sha256:<hex>` hash，不存明文。
3. 登录失败统一返回「用户名或密码错误」，不区分哪个错、不泄露账号是否存在。
4. 防暴力破解：连续失败累计 `failed_attempts`，达到阈值（建议 5 次）锁定 15 分钟（`locked_until` + `status`）。
5. 登录成功重置 `failed_attempts`、更新 `last_login_at`。
6. 会话有 `expires_at`（建议 24h），`revoked_at` 支持登出；过期或已撤销的会话立即拒绝。
7. 每次登录成败、登出都写 `audit_log`（含 IP、UA）。

## 功能与接口设计
### data 服务（Spring，`/internal/v1/auth/*`）
- `POST /auth/login`（username、password、ip、user_agent）→ 校验账号状态/密码 → 成功签发随机 token、写入 `auth_sessions`、记审计 → 返回 `{ token, expires_at }`；失败记审计并返回统一错误。
- `POST /auth/verify`（token）→ 按 `token_hash` 查会话，检查 `expires_at`/`revoked_at` → 返回 `{ account_id, username }`；可选刷新 `last_seen_at`。
- `POST /auth/logout`（token）→ 置 `revoked_at`、记审计。

### engine 服务（FastAPI，`/api/v1/*`）
- `POST /api/v1/login`：转发 data 登录，返回 `{ token, expires_at }`。
- `POST /api/v1/logout`：转发 data 登出。
- 新增 FastAPI 依赖 `require_login`：从 `Authorization: Bearer <token>` 取 token → 调 data `verify` → 注入当前账号；替换所有现有 `_require_token` 调用点。

## 验收标准
1. 未登录/无效/过期/已撤销会话访问 `/api/v1/*` 返回 401。
2. 正确账号密码能登录并拿到会话令牌，令牌可访问受保护接口。
3. 错误密码连续 5 次触发锁定，锁定期间正确密码也被拒；锁定到期后可登录。
4. 登录失败不泄露「账号是否存在」。
5. `audit_log` 完整记录登录成败与登出（含 IP、UA）。
6. 数据库中无明文密码、无明文令牌。
7. 初始账号按 `db/postgresql/setup/README.md` 的 `crypt(:'owner_password', gen_salt('bf', 12))` 手动创建，仓库无任何凭证。

## 边界（不做什么）
- 不做公开注册、不做多角色 RBAC（只有所有者）。
- 不做 OAuth/SSO/第三方登录、不做 MFA、不做密码找回。
- 不做记住我、多端并发会话治理。

## 产出物
1. data 服务：`/internal/v1/auth/*` 三个接口实现 + 单元测试。
2. engine：`/api/v1/login`、`/api/v1/logout`、`require_login` 依赖 + 测试，替换 `_require_token`。
3. 文档：说明登录流程、会话生命周期和初始账号创建步骤。
