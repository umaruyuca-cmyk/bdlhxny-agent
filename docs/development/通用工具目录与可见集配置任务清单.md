# 通用工具目录与可见集配置任务清单

依据 2026-08-21/22 所有者方向讨论生成,设计输入为《通用 Agent Mock Tools 评测设计》
(外部文档,经可行性核对)与现有架构。定位:**把"工具目录内容"与"工具可见集"从
代码常量升格为实验变量**——评测全 mock、选取可配置、同题异勾选对照。
承接《核心功能任务清单》(可与其穿插,可见集落库依赖其中"统一运行工件"的
fixed_conditions 扩展更佳,但不阻塞)。

## 总体策略(所有卡片共同遵守)

1. **评测全 mock 是明确策略**:所有工具返回一律来自冻结表(fixture sets),
   真实工具只留给现场演示且永不与 mock 批次混编(架构文档既有红线升格为明文);
2. **mock 只停在执行层**:冻结返回不打 `MOCK/TEST_FIXTURE` 质量标记,
   防止反 mock 防线(NON_PRODUCTION_DATA)误伤评测组;
3. **单一变量纪律**:每次对照只动一个旋钮(可见集/目录规模/装载策略),
   配置随批次落库、随工件记录,指标可归因;
4. **幻觉口径不合并**:"选错存在的工具"与"编造不存在的工具"与"调用目录内但
   本次不可见的工具"三个口径分开统计;
5. 涉及 DDL 与数据 SQL 一律写入 `db/postgresql/changes/` 交付所有者手动执行,
   代码不得直连库执行;验收用单元测试或事务内 dry-run 回滚。

## GT-3 负例 mock 支持(空结果/失败/超时/部分成功)

**背景**:现有 18 条冻结全 SUCCESS;评测文档 §4.2 要求空数据/超时/部分成功/
参数错误路径;`FrozenObservations` 丢弃非 SUCCESS 行(`__init__` 内
`!= "SUCCESS": continue`),负例进不去。

**改动步骤**:
1. **引擎**:`FrozenObservations` 保留非 SUCCESS 行,按 call_key 同规则查找;
   命中负例行时返回 `{"status": <response_status>, **response}`(失败信息进
   Observation,**不打 MOCK 标记**);空结果 = SUCCESS 行 + 空内容,天然支持;
2. **守卫调整**:`test_frozen_fixture_sync` 的"seed 全 SUCCESS"断言改为
   按 fixture set 区分(ab-eval 保持全 SUCCESS;负例集独立);
3. changes/ SQL `20260822-fixture-negative.sql`:新建冻结集
   `ab-eval-negative-v1`(STATIC),负例行:不存在代码 FAILED(symbol not found)、
   超时 TIMEOUT、空新闻 SUCCESS+`{"items":[]}`、部分成功组合键;
4. changes/ SQL 用例:四类负例题各 2 道(case_definitions/versions,
   `expected_checks` 增 `expected_behavior: "report_empty"|"report_failure"` 类
   金标;判官 v1 按现有口径:工具选对+数字接地自动罚编造);
5. 超时不做墙钟延迟(simulated_latency_ms 只记录)。

**验收**:单元测试覆盖四类负例的 FrozenObservations 查找与返回形状;
ReAct 失败回填后继续循环的既有测试仍绿;SQL 交付。

## GT-4 工具可见集配置后端

**背景**:完整模式装载策略写死 `tool_loading="scoped"`(ab_eval);裸调用组
可见集写死全量;`case_versions.allowed_tools` 字段存在但 runner 未消费;
/lab 无工具清单来源。

**改动步骤**:
1. **请求字段**:`EvalBatchRequest` 增加 `visible_tools: list[str] | None`
   (max 200,元素非空;None=默认策略 scoped);`start_eval_batch` 校验工具名
   ⊆ 目录(catalog 已加载),未知名 400(复用 case_ids 校验模式);
2. **runner 消费**:`run_ab_eval` 增加 `visible_tools` 参数:裸调用组
   `all_cards` 过滤;完整模式组 AgentLoop 增加 `visible_override` 参数,
   scoped 结果 ∩ 勾选集(G1 仍按最终可见集拦截);ReAct 组与裸调用同过滤;
3. **落库**:`create_batch` 的 fixedConditions 增加 `visibleTools`
   (null 或名单);工件 payload 增 `visible_tools` 字段;
4. **判官新口径**:`invisible_tool_rate`——attempted − 本次可见集(与
   hallucinated/outside-catalog 分开统计;三组分别按执行日志/attempted/审计算);
   进 `_agg_runs` 与报告;
5. **工具端点**:`GET /api/v1/tools`(require_login):engine 代理
   `DataClient().get_tool_catalog()`,返回 `[{name, description, domain,
   enabled}]` 供前端勾选;
6. 测试:未知名 400;三组可见集过滤生效(Fake 模型);invisible 口径计算。

**验收**:engine 测试全绿;/lab 用 CLI/curl 发一批带 visible_tools 的请求,
fixed_conditions 与工件中可见集正确(SDK 侧冒烟由所有者或自动化 dry 模式完成)。

## GT-6 通用工具目录 96 个 Mock 工具

目录新字段(mock_only/side_effect/requires_confirmation/risk_level)现表没有。

**改动步骤**:

   CHECK IN ('none','write','external_action')`、`requires_confirmation BOOLEAN
   DEFAULT FALSE`、`risk_level VARCHAR(10) DEFAULT 'low' CHECK IN

   fixture set 表达);写入型工具的操作证:新增操作码行(如 WRITE_COMMUNICATION/
   WRITE_SCHEDULE/WRITE_FILE 等)并说明 `RUNTIME_ALLOWED_OPERATIONS` 需同步扩,
   否则启用技能校验会拒启动——**v1 建议写入工具所在技能默认 enabled=false,
   仅用例按需启用**,避免动运行时允许集;
2. **工具数据 SQL**(changes/ `20260822-generic-mock-tools.sql`):96 个工具按
   设计文档 §4.2-4.20 的方向/名称/参数逐条插入(统一 `领域.动作` 命名;金融 16

   (金融 16 不变;96 通用工具按名字集合守卫,与 SQL 同步);

## GT-7 判官指标全量扩展

**背景**:现口径仅集合相等/目录外幻觉/越权;设计文档 §8 定义五组指标;
金标需按用例写厚(expected_params/expected_order/confirmation_present)。

**改动步骤**(全部在 `ab_eval` 判定层,纯确定性计算):
1. **选择组**:精确率/召回率/漏选率/多余调用率(基于成功集合 vs 金标集合的
   交并差;fastpath 题保持零调用判定);
2. **幻觉组**:三分口径落地(目录外/目录内不可见(GT-4)/禁止工具尝试
   (absent_tools ∩ attempted));
3. **参数与流程组**:参数完整率(必填参数存在)、类型正确率(JSON Schema
   校验,能力行 required_arguments + parameters)、重复调用率(同工具同参数
   重复);顺序正确率(多步用例 expected_order,从 case_steps 金标);
   参数事实一致率 v1 仅对带 expected_params 金标的用例启用;
4. **权限与确认组**(v1 只判不拦):越权调用率(既有)、未确认写入率
   (调用 side_effect≠none 工具且用例上下文无确认)、查询误用写入率;
   拦截成功率延后(引擎确认门控属 v2);
5. **检索组**:search_tools 命中率/无效检索/重复检索/检索后选择准确率/
   工具描述 token —— 需要 runner 记录 search_tools 调用细节(call_log 已含,
   补金标字段 expected_search)与每轮可见 schema token 估算;
6. **报告与渲染**:`_agg_runs`/`_report_payload`/render 扩列;showcase
   results 页指标表按需增行(读 schema 白名单字段,页面改动随核心清单
   七模块落地一并,不阻塞本卡)。

**验收**:每指标至少一个正例一个反例单元测试(构造 call_log/audit 金标);
报告 JSON 含新字段且旧字段不破坏(schema 校验按需扩展);
