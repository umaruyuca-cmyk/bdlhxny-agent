# 开发计划与验收标准

## 1. 当前代码基础

当前 `touchstone` 分支已经保留：

- Python Agent 循环；
- 语义快路径；
- `scoped` 和 `search` 工具装载；
- 工具目录；
- 工具执行前后的代码检查；
- Observation 标准化；
- 裸 tool calling、LangGraph ReAct 和完整工程模式对照；
- 18 道固定题基础；
- 静态文档展示页面和前端契约测试；
- `data` 固定题库、运行和上下文记录服务，数据库表由 Flyway 管理；
- 上下文构建基础包及强制项、预算、隔离测试；
- 只接受固定题号的私有运行 API；
- 本地完整环境、云镜像和纯公开站三种部署配置。

当前缺少或需要替换：

- Python 执行包中仍有一份兼容题目定义，需要改为完全由数据服务用例生成；
- 内部 Agent 循环仍支持 `message` 和历史消息，但对外 API 已禁止这些字段；
- 上下文构建基础包尚未接入 Agent 循环和实际模型 tokenizer；
- 没有统一运行工件和上下文处理报告；
- 没有严格区分有效运行和基础设施无效运行；
- 没有公开发布的脱敏与 hash 校验流程；
- 当前 `/docs` 页面仍是旧展示结构，目标是 `/showcase`；
- 旧评测报告受到 429 和评测口径问题影响，不能作为正式基准。

## 3. 开发阶段

### 阶段 0：固定文档和数据边界

工作内容：

- 删除旧设计和旧评测报告；
- 以本目录六份编号文档为新设计依据；
- 更新仓库 README 的设计入口；
- 明确原始工件、公开工件和设计文档的不同位置。

完成标准：

- `docs/` 只包含新设计文件；
- 所有文档链接有效；
- README 不再指向已删除的旧文档和旧报告。

### 阶段 1：独立固定用例目录

工作内容：

- 定义 `CaseDefinition` 和 `CaseVariant` schema；
- 把 `AB_CASES` 迁移到 `engine/cases/`；
- 运行页面、评测器和测试读取同一目录；
- 增加 schema、唯一编号和公开字段测试。

完成标准：

- 评测代码中不再手写第二份题目；
- 用例缺字段、重复编号或未知工具时测试失败；
- 现有18题全部成功迁移；
- 新增长上下文、冲突、注入和故障变体。

### 阶段 2：统一运行工件和耗时记录

工作内容：

- 定义运行工件 schema；
- 在裸调用、ReAct 和完整工程模式中使用同一记录接口；
- 记录各阶段时长、token、重试和错误；
- 增加 `VALID/INVALID` 判断；
- 生成批次报告 JSON。

完成标准：

- 每个运行都有 `run_id`、用例版本、快照 hash、Git commit 和模型配置；
- 429、余额不足和服务不可用被标记为无效；
- 报告只使用有效运行计算能力指标；
- 工件 schema 和 hash 测试通过。

### 阶段 3：上下文构建器基础版本

工作内容：

- 新增上下文条目和上下文处理报告；
- 把当前 `_assemble_messages` 前的直接拼装改为上下文构建器；
- 第一版只做完整透传，但准确记录原始 token 和工作 token；
- 增加强制项、来源和指令隔离校验；
- 为每个场景建立规则文件。

完成标准：

- Agent 行为与当前实现基本一致；
- 所有模型输入都经过上下文构建器；
- 系统规则、固定问题和权限不能被省略；
- 上下文处理报告进入运行工件。

### 阶段 4：按预算选择和压缩

工作内容：

- 接入模型 tokenizer；
- 实现结构化摘要、引用和省略；
- 实现 `priority / token` 选择；
- 增加循环内 Observation 再压缩；
- 实现缓存和版本失效；
- LLM 文本摘要作为可选策略，失败时回退。

完成标准：

- 强制项超过预算时明确失败；
- 任何策略都不删除安全和权限规则；
- 缓存键包含用例、快照、规则、工具和 tokenizer 版本；
- 每个省略和降级都能在报告中解释；
- 长上下文单元测试覆盖开头、中间、末尾关键事实。

### 阶段 5：私有运行入口

工作内容：

- 增加登录和所有者权限；
- 增加只接受 `case_id` 的运行 API；
- 增加批次、取消、并发和总 token 上限；
- 增加 `/lab` 和内部运行详情页；
- 公网配置不部署运行 API。

完成标准：

- 未登录请求创建运行返回 401/403；
- 请求包含 `message`、`prompt` 或自定义工具时返回 400；
- 修改前端代码不能绕过后端鉴权；
- 重复幂等请求不会产生重复计费运行；
- 公网镜像不包含模型密钥和运行服务。

### 阶段 6：评测重建

工作内容：

- 分开 Agent 实现方式对照和上下文策略对照；
- 增加固定数据快照和交错运行顺序；
- 增加5次有效重复门槛；
- 扩展任务、工具、上下文、安全和故障用例；
- 修正过度归因和无效 token 统计；
- 产出第一批无污染正式工件。

完成标准：

- 单一实验只改变一个变量；
- 每组有效样本数达标；
- 无效运行在报告中单列；
- 0% 到 0% 不描述为改善；
- 所有汇总数字可以定位到运行工件；
- 上下文策略报告包含净成本而不只是压缩率。

### 阶段 7：公开展示和发布

工作内容：

- 新建 `/showcase` 页面；
- 新建结果、用例、运行和上下文页面；
- 实现字段白名单、敏感信息扫描和 hash 校验；
- 生成公开索引和静态运行工件；
- 页面不调用运行 API；
- 增加页面和数据契约测试。

完成标准：

- 断开后端后公开页面仍可完整浏览；
- 浏览行为不产生 LLM 调用；
- 所有公开数字从 JSON 渲染；
- 可以查看获胜、退化、平局、双方失败和无效运行；
- 公开工件不含内部完整 Prompt、真实用户数据和密钥；
- 最新首页批次必须是满足有效性门槛的批次。

### 阶段 8：演示门禁

工作内容：

- 编写一键检查脚本；
- 固定面试演示顺序；
- 录制固定用例、上下文对照和展示页讲解；
- 验证无网络、模型限流和工具故障时的切换路径。

完成标准：

- 门禁检查固定用例、工件、公开页面、登录和权限；
- 至少连续完成3次完整彩排；
- 现场运行失败时能在10秒内切换到冻结工件或录屏；
- 演示过程中不依赖公开访客输入。

## 4. 代码改造重点

### 4.1 移除产品层的通用聊天

当前 `AgentTurn` 仍包含 `message` 和 `history`。迁移方式：

- 内部 Agent 循环可以继续接收已经解析的文本；
- 对外运行 API 只接受 `case_id`；
- 运行控制器从固定用例目录生成内部 `AgentTurn`；
- 产品页面不提供聊天输入框；
- `history` 只用于预设多步用例的迁移期兼容，最终改为结构化的上一步状态；
- 旧聊天入口不再公开路由，确认无调用后删除。

### 4.2 不把上下文算法写进 Agent 循环

`AgentLoop` 只消费构建好的消息。上下文收集、压缩和校验放在独立 `context/` 包中，便于四种策略共用和对照。

建议接口：

```python
class ContextBuilder(Protocol):
    async def build(self, request: ContextBuildRequest) -> ContextBuildResult: ...
```

### 4.3 统一运行事件

裸调用、ReAct 和完整工程模式需要发出相同类型的可观察事件：

- `run.started`；
- `context.completed`；
- `model.completed`；
- `tool.requested`；
- `tool.completed`；
- `guardrail.completed`；
- `output.completed`；
- `judgment.completed`；
- `run.completed`。

事件只记录可观察过程，不记录隐藏思维。

## 5. 测试清单

### 5.1 固定用例

- schema 校验；
- 编号唯一；
- 工具名称存在；
- 公开字段不含敏感内容；
- 页面和评测读取同一目录。

### 5.2 上下文

- 强制项永不被普通分数淘汰；
- token 不超过预算；
- 数字、时间和引用一致；
- 不可信文本不能进入指令区域；
- 缓存正确命中和失效；
- LLM 摘要失败可以回退；
- 多步用例不复制全部历史；
- 循环中工具结果增长时仍满足预算。

### 5.3 运行和权限

- 游客不能创建运行；
- 任意问题正文被拒绝；
- 重复请求幂等；
- 超时、取消和重试有记录；
- 无效运行不计入指标；
- 公网部署无运行 API。

### 5.4 工件和发布

- 工件字段完整；
- hash 可复算；
- 公开字段白名单；
- 敏感信息触发发布失败；
- 汇总指标可回算；
- 页面断开后端仍工作。

## 6. 工程门禁

现有命令继续保留：

```powershell
Set-Location engine
uv run ruff check .
uv run python -m pytest -q

Set-Location ../web

```

实施新模块后增加：

- 固定用例 schema 测试；
- 上下文预算和属性测试；
- 工件 JSON Schema 测试；
- 公开敏感信息扫描；
- 静态站不能调用运行 API 的契约测试；
- 正式批次有效样本门禁。

## 7. 完成定义

只有同时满足以下条件，新的设计才算实现完成：

1. 项目所有者只能通过固定用例创建运行；
2. 公开访问者不能创建运行或产生 token 成本；
3. 所有模型输入都经过统一上下文构建器；
4. 长上下文压缩可以解释每个保留和省略决定；
5. 强制约束和来源在压缩后保持完整；
6. Agent 对照和上下文对照分别运行；
7. 基础设施无效运行不污染能力指标；
8. 所有公开结果来自通过脱敏和 hash 校验的运行工件；
9. 公开页面可以从汇总指标下钻到单次运行；
10. 文档、固定用例、测试和页面使用同一套名称与数据定义。
