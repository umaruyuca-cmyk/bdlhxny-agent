# 规模实验操作手册（GT-8 交付）

> 适用范围：通用工具目录规模档位实验（8/24/48/112 + 搜索装载档）。
> 档位建议勾选清单见《通用工具目录与Mock评测》§9.1；
> 第一阶段用例集为 `gt8-*`（72 道，第二批口语/混淆表达补齐至 160-180）。

## 1. 成本护栏

**真实规模批次一律由所有者手动发起，本手册不构成自动化授权。**
若核心清单的批次 token 上限已可用（`max_total_tokens` 请求字段 /
`EVAL_MAX_TOTAL_TOKENS` 环境变量），发起规模批次时**优先启用**——
预算耗尽会停止发起新运行（部分完成语义），不会产生无效样本。

### token 量级预估

单次运行成本 ≈ 工具定义 token（当轮可见 schema 估算，判官
`tools_schema_tokens` 口径）× 模型轮次 + 问题/历史 + 答案。保守口径
（ConservativeTokenCounter，CJK 1 token/字、拉丁 4 字符/token）下每工具
定义约 120-200 token：

| 档位 | 可见工具 | 工具定义 token/轮(估) | 单题 1 次 × 3 组(估) | 72 题 × 1 次(估) |
|---|---:|---:|---:|---:|
| 小目录 8 | 8 | ~1.4K | ~10K | ~0.7M |
| 中目录 24 | 24 | ~4K | ~25K | ~1.8M |
| 大目录 48 | 48 | ~8K | ~50K | ~3.6M |
| 超大 112 | 112 | ~18K | ~110K | ~8M |
| 搜索装载 | 1(元工具) | ~0.3K(+检索结果) | ~5K | ~0.4M |

注：多轮调用会重复计入工具定义 token（每轮 bind_tools 全量）；上表按
平均 2.5 轮/题放大。建议首次实验先跑 `runs=1` 单档观察实际 token，再按
量级表扩展；每题重复次数（runs）线性放大总量。

### 建议梯度

1. 小目录 × gt8 相似区分 24 题 × runs=1（<0.3M）——先验证链路；
2. 中/大目录 × 同题集 × runs=1——观察选择退化；
3. 超大 112 × 全 72 题 × runs=1（~8M）——一次即可，开 token 上限；
4. 需要统计显著性时再对关键对照补 runs（2-3），不做无差别重复。

## 2. 发起步骤（/lab）

1. 登录 `/lab`（私有侧），题号勾选目标用例子集（如 `gt8-sim-*` 24 题）；
2. 「工具可见集」按 §9.1 档位清单勾选（快捷键：全选→手动取消非清单项；
   档位清单可复制到本地对照勾选）；
3. 「冻结数据集」按需选择（通用目录实验用 `mock-eval-v1`；负例对照
   `ab-eval-negative-v1` / `mock-eval-negative-v1`）；
4. 「批次 token 上限」按上表填入预算（如 8M 档填 8000000）；
5. 「检索档 top_k」仅搜索装载档实验时设置（1-8；缺省=模型自报）；
6. 发起批次；执行中可协作取消（已开始的模型调用等待完成）；
7. 完成后结果页/报告 JSON 的「通用目录专项（GT-7）」节查看各档指标；
   发布公开实证层走既有发布脚本流程。

## 3. 单一变量纪律

- 每次对照只动一个旋钮：档位 / 冻结集 / top_k / 装载策略；
- 配置随批次落库（fixedConditions 的 visibleTools/fixtureSetId/searchTopK），
  指标可归因；
- 四档共享同一金标题集（gt8-\*），跨档对比才有意义；
- 不要同时改变工具数量、Prompt、模型和上下文策略（评测文档 §13）。

## 4. 已知边界（记档）

- 完整模式组按 `scoped(scene) ∩ 勾选集` 装载，通用工具不在场景映射内：
  含通用工具的档位下完整模式组可见集小于裸调用/ReAct 组——跨组同集
  结论以裸调用 vs ReAct 为主（GT-6 修订记录(九)⑦）；
- 通用工具依赖 GT-6 两份 SQL 已由所有者执行（96 能力行 + 冻结集）；
  未执行前 gt8-\* 中引用通用工具的题不可正常对照；
- 检索组指标 v1 按调用记录近似（GT-7 修订记录(十)③）。
