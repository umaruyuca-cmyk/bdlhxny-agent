# Touchstone 设计文档

> 状态：目标设计，作为后续开发和验收的唯一设计依据  
> 适用分支：`touchstone`  
> 更新日期：2026-08-20

Touchstone 是一个面向 Agent 工程实践的固定用例评测与展示系统。项目所有者登录后运行预先登记的用例，系统记录模型输入、上下文压缩、工具调用、代码拦截、运行时长和最终结果。公开访问者只能浏览经过脱敏的实验结果，不能输入问题，也不能触发模型或工具。

本目录只保存设计文档。评测结果、运行记录和录屏不放在 `docs/` 中，避免把设计与实验产物混在一起。

## 五个核心决定

1. **不提供公开输入框。** 公开站点只读取静态数据，不连接运行服务。
2. **运行只接受固定用例编号。** 登录用户提交 `case_id`，问题正文由服务端固定用例目录读取，不能从请求中传入任意问题。
3. **一次用例就是一次独立运行。** 产品不维护通用聊天会话；需要测试多轮能力时，使用预先登记的多步用例。
4. **上下文按预算构建。** 系统先收集原始数据，再按场景保留、压缩或引用，最后生成模型实际使用的上下文。
5. **结果必须可以追溯。** 汇总指标可以下钻到单次运行；无效运行、失败案例和完整对照分布都必须保留。

## 常用术语

| 术语 | 本文中的含义 |
|---|---|
| 固定用例 | 由仓库预先登记的问题、场景、权限、工具范围、上下文来源和评测条件 |
| 用例变体 | 同一个问题在短上下文、长上下文、冲突数据或故障条件下的不同输入数据 |
| 数据快照 | 一次运行开始时冻结的持仓、画像、记忆、行情、新闻和模拟工具数据版本 |
| 原始上下文 | 运行可使用的全部候选信息，通常不能全部发送给模型 |
| 工作上下文 | 经过选择和压缩后，实际发送给模型的信息 |
| 上下文条目 | 一条带来源、时间、类型、重要性和 token 数的信息 |
| 运行记录 | 一次运行的输入条件、上下文处理、模型轮次、工具调用、拦截、结果和指标 |
| 运行工件 | 冻结为 JSON 的运行记录，用于评测、回放和公开展示 |
| 无效运行 | 因 429、余额不足、服务不可用或评测器失败而不能用于能力统计的运行 |

## 文档和数据的存放规则

| 内容 | 目标位置 | 是否进入公开站点 |
|---|---|---|
| 设计文档 | `docs/` | 否，供开发阅读 |
| 固定用例定义 | `sentinel-engine/cases/` | 只发布允许公开的标题和问题 |
| 本地原始运行工件 | `sentinel-engine/var/artifacts/` | 否，默认加入 `.gitignore` |
| 公开运行工件 | `sentinel-console/public/showcase-data/` | 是，由发布脚本生成 |
| 录屏 | `recordings/` | 按部署方式单独托管，不进入设计目录 |

## 文档维护规则

- 本目录中的六份编号文档共同构成目标设计，不再保留历史报告或过期设计。
- 新术语必须在首次出现时用普通语言解释；能用“固定用例”“上下文条目”“运行记录”表达时，不创建新的品牌化名称。
- 代码与设计不一致时，在 `05-实施计划与验收标准.md` 登记差距，不在多份文档中复制不同版本的结论。
- 评测数字只来自机器生成的运行工件。设计文档不手写“最新结果”。
